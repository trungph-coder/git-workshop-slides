Phần 2 - Bản chất dữ liệu

Git lưu ảnh chụp, không lưu bản vá

  • SVN, CVS lưu file gốc rồi chồng các bản vá (delta). Muốn xem phiên bản 100 phải cộng dồn 100 bản vá.
  • Git chụp toàn bộ hệ thống file ở mỗi commit.
  • File có thay đổi: Git lưu bản mới.
  • File không đổi: Git chỉ trỏ tới bản đã lưu ở commit trước, nên rất tiết kiệm dung lượng.
diff vs snapshot

Phần 2 - Commit bất biến

Không có chuyện "sửa" commit cũ

Mã hash của commit được tính từ 5 thành phần. Đổi một ký tự trong bất kỳ thành phần nào là ra hash khác.

  • Mọi thao tác "sửa" thực chất là tạo commit mới với hash mới.
  • Vì hash chứa hash commit cha, đổi một commit là đổi toàn bộ chuỗi phía sau. Đây là lý do rebase và --amend đổi hash.
hash = SHA(...)

Phần 2 - Bức tranh 4 vùng

Mỗi dòng code đi qua 4 vùng

  • Working Directory: file bạn đang sửa trên IDE. Chưa được Git bảo vệ.
  • Staging Area (.git/index): khu dàn cảnh cho bức ảnh sắp chụp.
  • Local Repo (.git): git commit đóng gói Staging thành snapshot vĩnh viễn.
  • Remote Repo: GitHub, GitLab. Cầu nối để cả team đồng bộ.

Phần 2 - Con trỏ HEAD

HEAD trả lời: "Tôi đang đứng ở đâu?"

  • Bình thường HEAD trỏ vào tên nhánh (HEAD -> main), còn nhánh trỏ vào commit mới nhất.
  • Commit mới: nhánh tiến lên, HEAD đi theo nhánh.
  • git switch sang nhánh khác: HEAD chuyển sang tên nhánh đó, Working Directory đổi theo.

Phần 2 - Detached HEAD

Detached HEAD: HEAD rơi tự do

  • Xảy ra khi checkout thẳng vào một hash hoặc tag: git checkout a1b2c3d.
  • Rủi ro: commit tạo ở trạng thái này không có nhánh nào trỏ tới. Quay về main là chúng thành "commit mồ côi", bị Garbage Collector xóa sau một thời gian.
  • Khắc phục: muốn phát triển tiếp từ commit cũ, tạo nhánh ngay: git switch -c feat/ten-nhanh-moi.

Phần 3 - pull vs pull --rebase

git pull sinh commit rác, --rebase thì không

  • git pull = fetch + merge. Remote có commit mới và bạn cũng có commit chưa push: Git tạo commit "Merge branch 'develop' of...". 10 người chung nhánh là hàng trăm commit vô nghĩa.
  • git pull --rebase = fetch + rebase. Kéo commit đồng đội về trước, đặt commit của bạn lên trên cùng.

Phần 3 - git cherry-pick

cherry-pick: bốc đúng một commit

  • Chọn đích danh một hoặc vài commit từ nhánh khác, áp vào nhánh hiện tại, không cần merge cả nhánh.
  • Ví dụ: feat/v2 còn làm dở, nhưng có commit 8f9a1b2 vá lỗi bảo mật. Đứng ở main, bốc riêng bản vá đó đi deploy.

Phần 3 - git worktree

worktree: nhiều nhánh, nhiều thư mục, một .git

  • Nỗi đau: đang code dở, server đang chạy, có hotfix gấp. stash rồi checkout thì IDE index lại, server build lại từ đầu.
  • Giải pháp: checkout nhiều nhánh cùng lúc ra nhiều thư mục, dùng chung một cơ sở dữ liệu .git. Tiết kiệm dung lượng, đồng bộ tức thì.

Phần 3 - git tag

tag đứng yên, branch thì chạy

  • Đóng dấu cột mốc phát hành (v1.0.0, v2.1.4). Branch đi theo commit mới, tag đứng yên vĩnh viễn.
  • Lightweight: chỉ là cái tên trỏ tới hash (git tag v1.0.0).
  • Annotated (khuyên dùng): object riêng, lưu người tạo, email, ngày giờ, thông điệp.
  • git push mặc định không đẩy tag. Phải đẩy riêng.

Phần 4 - Branching strategy

GitHub Flow / GitLab Flow: 3 làn

  • main: code đang chạy Production. Luôn ổn định, deploy được bất cứ lúc nào. Protected Branch, cấm push thẳng.
  • develop (tùy quy mô team): nhánh tích hợp cho Staging / Testing.
  • Feature / Fix: tách từ main hoặc develop, xong thì mở Pull Request / Merge Request để review trước khi gộp.
feature -> PR -> develop -> main

Phần 4 - Quy trình hằng ngày

6 bước cho mỗi task

  1. Cập nhật nhánh gốc mới nhất.
  2. Tạo nhánh riêng theo quy tắc đặt tên.
  3. Code và commit theo cụm logic nhỏ, git add -p để soát kỹ.
  4. Đồng bộ lại trước khi tạo PR: rebase lên nhánh gốc, xử lý conflict ở local.
  5. Push và tạo PR: mô tả thay đổi gì, cách test, ảnh/video nếu là UI.
  6. Review và merge: ít nhất 1 approve, CI xanh, Squash and Merge, xóa nhánh tạm.

Phần 5 - Git Hooks

Hooks: trạm kiểm soát tự động

  • Script Git tự chạy trước/sau một sự kiện (commit, push, receive). Nằm trong .git/hooks/.
  • pre-commit: linter, formatter, quét secret. Exit code khác 0 là chặn commit.
  • commit-msg: kiểm tra Conventional Commits (commitlint).
  • pre-push: chạy unit test nhanh. Server: pre-receive chặn force push trái phép.
